# M17

M17 conventional operation on the air interface ([air-interface.md](air-interface.md)): stream mode (voice), packet
mode (text messages) and BERT mode (bit error rate test). Source: *M17 Protocol Specification, Part I: Air
Interface*, version 2.1.1 (19 November 2026), cited below as "M17" with its section numbers. Switch: `CONFIG_M17`,
with `CONFIG_M17_PACKET` and `CONFIG_M17_VOICE` ([build-config.md](../build-config.md)). Which radios could carry it:
[feature-matrix.md](../feature-matrix.md).

**Licence of the source.** The M17 document is GFDL-1.3-or-later; its code samples (appendix listings) are
GPL-2.0-or-later. This page is written in our own words from the document's prose, tables and formulas. Numeric
protocol constants (sync words, polynomials, puncture patterns, the randomizer sequence, the interleaver formula, the
address alphabet) are interoperability facts and are used as such. Never copy the document's text or code, and never
open another M17 implementation's source ([CLEANROOM.md](../CLEANROOM.md)).

## 1. On air

| Item | Value | M17 |
|---|---|---|
| Modulation | 4FSK, 4800 symbols/s (9600 bit/s), modulation index 1/3 | 1.1 |
| Deviation | outer symbol ±2400 Hz, inner ±800 Hz | 1.2 |
| Symbol map | `01` +3, `00` +1, `10` -1, `11` -3, first dibit in bits 7-6 of a byte: the air interface's own map ([air-interface.md](air-interface.md) 2) | 1.2, table 1.1 |
| Pulse | root raised cosine, roll-off 0.5, at both ends | 1.3 |
| Channel | 9 kHz occupied, 12.5 kHz spacing | 1.1 |
| Frame | 8-symbol sync + 368 payload bits = 192 symbols = 40 ms | 2.1 |
| Byte order | big endian; bits most significant first | 2.3 |

### 1.1 Profile

The mode's `air_profile_t` (`core/m17/m17_air.c`):

| Field | Value | Why |
|---|---|---|

| `shape`, `shape_param` | `AIR_SHAPE_RRC`, 50 | M17's pulse. Every chip provider answers `AIR_FIT_SHAPE_APPROX` (6.1) |
| `dev_outer_hz` | 2400 | |
| `timing`, `slot_syms` | continuous, 0 | |
| `bw` | 12.5 kHz | 9 kHz occupied fits; a receiver whose copy clips the spectrum may want the wider filter (5.4) |
| `sync_every_syms` | 0 | No 24-symbol pattern recurs: a correlator that needs one can't receive M17 (5.1) |
| `sync_any_syms` | 192 | A sync opens every frame |
| `sync_period_syms` | 192 | Every frame is exactly 192 symbols: the soft modem fits only near the next one while locked (5.3; a field this mode adds) |
| `idle` | `0x77` (+3 -3 +3 -3) | The preamble pattern: a provider's lead-in reads as more preamble, and a tail after the end marker is harmless (6.2) |
| `id` | `AIR_PROFILE_M17` | Per-profile on-air marks ([air-interface.md](air-interface.md) 4; a field this mode adds) |

Patterns, most useful first (`air_sync_t`):

| Id | Pattern | Symbols | Hex | Errors | Flags | Use |
|---|---|---|---|---|---|---|
| 0 | Stream | 8 | `FF5D` | 1 | | every stream frame; late entry |
| 1 | LSF, with the preamble's tail | 24 | `7777 7777 55F7` | 2 | start only | the link setup frame after a preamble |
| 2 | Packet | 8 | `75FF` | 1 | | every packet frame |
| 3 | BERT, with the preamble's tail | 24 | `DDDD DDDD DF55` | 2 | start only | the first BERT frame |
| 4 | BERT | 8 | `DF55` | 1 | | every later BERT frame |

The stream word is the LSF word with every symbol negated, and BERT the packet word negated (5.3). All are outer
symbols only.

## 2. Frame fields and FEC

All payload coding reuses `core/fec` ([air-interface.md](air-interface.md) 1). Only the CRC, the puncture patterns,
the interleaver and the randomizer are new, in `core/m17/m17_frame.c`.

| Step | What | Where |
|---|---|---|
| CRC | 16 bit, polynomial `0x5935`, initial `0xFFFF`, not reflected, no final XOR. Check values: empty input `0xFFFF`, `A` `0x206E`, `123456789` `0x772B`, the bytes 0 to 255 `0x1C31`. A whole valid LSF (CRC included) gives 0 | M17 2.6 |
| Convolutional code | rate 1/2, constraint length 5, G1 = 1 + D³ + D⁴, G2 = 1 + D + D² + D⁴, output G1 then G2, four zero tail bits. This is `fec_conv` with masks `{ 0x19, 0x17 }`, the code NXDN uses ([nxdn.md](nxdn.md) 2) | M17 app. C |
| Golay | extended Golay(24,12): data bits 23-12, check bits 11-1, parity bit 0. Bit for bit `fec_golay24_encode` / `fec_golay24_decode` (each of the 12 generator rows checked) | M17 app. D |
| Puncturing | P1 (LSF): 61 entries, 46 kept: a 1, then fifteen times `1 0 1 1`; applied over the 488 coded bits. P2 (stream, BERT): 12 entries, 11 kept (every twelfth bit dropped). P3 (packet): 8 entries, 7 kept (every eighth dropped). The decoder gives a dropped bit the soft value 0 | M17 app. E |
| Interleaver | quadratic permutation of the 368 payload bits: bit x goes to (45x + 92x²) mod 368 | M17 app. F |
| Randomizer | the 368 payload bits XOR a fixed 46-byte sequence, most significant bit first, the same for every frame (a table of 46 bytes) | M17 1.4.4, app. B |

Bit types: type 1 is the content, type 2 after the convolutional code, type 3 after puncturing, type 4 after
interleaving; randomizing comes last before the sync is added (M17 2.2).

## 3. Frames

### 3.1 Link setup frame (LSF)

| Bytes | Field | Notes |
|---|---|---|
| 0-5 | DST | destination address (7) |
| 6-11 | SRC | source address (7) |
| 12-13 | TYPE | 3.5 |
| 14-27 | META | 112 bits; its kind is TYPE's (3.5) |
| 28-29 | CRC | over bytes 0-27 |

Coding: 240 bits + 4 tail bits → convolutional code (488) → P1 (368) → interleave → randomize, behind the LSF sync.
One LSF per transmission, straight after the preamble (M17 2.5, 2.7).

### 3.2 Stream frame

| Part | Bits | Coding |
|---|---|---|
| LICH: 40 bits of the LSF (one sixth), LICH counter (3 bits, 0-5), 5 reserved bits (0) | 48 | four Golay(24,12) words: 96 |
| Frame number (16 bits: bit 15 set on the last frame, bits 14-0 count from 0 and wrap after 0x7FFF) + payload (128 bits) | 144 | + 4 tail bits, convolutional code (296), P2 (272) |

LICH 96 + payload 272 = 368 bits, interleaved and randomized together (M17 2.8.1). LICH counter n carries LSF bytes
5n to 5n + 4.

**Superframe.** Six stream frames carry one whole LSF, so a receiver that missed the LSF has it after at most
240 ms (M17 2.8.2). Only META may change during a stream, and only at a superframe boundary.

### 3.3 Packet frame

25 data bytes and a 6-bit field: on all but the last frame, bit 5 clear and bits 4-0 the frame number; on the last,
bit 5 set and bits 4-0 the number of valid bytes in it. 206 bits + 4 tail → 420 → P3 (368) → interleave → randomize.
A packet is 1 to 33 frames after its LSF: at most 823 bytes of data plus its CRC (3.4) (M17 2.9).

### 3.4 Packet contents

A data type (1 to 4 bytes, the UTF-8 length encoding; 0-127 in one byte), the data, then the CRC (2) over both
(M17 3.3.2). Data types used here:

| Type | Content | Here |
|---|---|---|
| 0x05 | Text message: UTF-8, ending with a NUL | sent and received (8.2) |
| others (RAW, AX.25, APRS, 6LoWPAN, IPv4, Winlink) | | received and dropped, counted |

### 3.5 TYPE

| Field | Values | Here |
|---|---|---|
| Packet or stream | | from the frame kind |
| Data type (stream) | 01 data, 10 voice (Codec 2 3200), 11 voice + data (Codec 2 1600 + 64 data bits) | voice played; voice + data shown, not played (12) |
| Encryption | none, scrambler, AES | none played; others shown as encrypted, not played |
| Subtype | key length, or the META kind when not encrypted | META: text and extended callsign read (3.6) |
| Signed stream | | the signature frames are not played (9.4); signatures not checked |
| CAN | 0-15 | 8.3 |

Exact bit positions: M17 3.1.2, tables 3.2-3.7, copied as values into `m17_frame.h`.

### 3.6 META

| Kind | Here |
|---|---|
| Text (up to 4 blocks of 13 bytes) | read; shown on the receive screen as it arrives |
| Extended callsign (originator, reflector) | read: the originator is shown in place of SRC when a reflector or gateway relays the call |
| Position | not read |
| None, nonce (encrypted) | |

### 3.7 BERT frame

197 bits of the PRBS9 sequence (x⁹ + x⁵ + 1) per frame, coded as a stream payload is: + 4 tail bits, convolutional
code (402), P2 (369), the last bit dropped (368), interleave, randomize. No LSF (M17 2.10, app. G).

## 4. A transmission

| Part | Symbols | Content |
|---|---|---|
| Preamble | 192 (40 ms) | +3 and -3 alternating. +3 first before an LSF, -3 first before BERT, so its last symbol is opposite the sync's first (M17 1.4, 2.4) |
| LSF | 192 | stream and packet transmissions only |
| Frames | 192 each | stream, packet or BERT frames |
| End of transmission | 192 | the word `555D` repeated (M17 1.4.5) |

## 5. Receive

### 5.1 Which receiver

A modem chip's own correlator takes only 24-symbol patterns of outer symbols that recur through a transmission
([air-interface.md](air-interface.md) 4, [modem-hrc6000.md](modem-hrc6000.md) 10.1). M17's recurring syncs are 8
symbols; the only 24-symbol run is a preamble's tail plus the LSF word, once per transmission. So M17 is received
through a board's discriminator tap and the soft modem (`AIR_FIT_RX | AIR_FIT_SOFT`). A board without a tap can
transmit M17 and not receive it.

The soft modem's fit (`air_softmodem_rx_fit`) needs the tap's band to reach 2640 Hz (0.55 × 4800) and, for four
levels, down to 48 Hz. The pulse's spectrum reaches 3600 Hz ((1 + 0.5) × 2400); a copy specified to 3000 or 3400 Hz
trims its tail (5.4).

### 5.2 Sync confirmation (the head hook)

An 8-symbol pattern with one error allowed turns up by chance in random data and noise several times a second. The
framer cuts a frame at every candidate, and the mode's head hook (`air_mode_t.head`) accepts it only on proof:

| Pattern | Confirmed by |
|---|---|
| LSF | the whole frame: the CRC over the decoded LSF is 0 |
| Stream | the LICH: all four Golay words decode, at most 2 bits corrected each (`fec_golay24_decode` returns 0-3, or -1; 3 and -1 are rejected); counter 0-5; reserved bits 0 |
| Packet | the Viterbi decoder's corrected-bit count under a limit; the next frame's sync found where expected (two frames); the packet's CRC at its end. A one-frame packet has no second packet sync: the end marker 39 to 41 ms later, its second word, and the same CRC confirm it |
| BERT | after a preamble only (the 24-symbol pattern), or two BERT frames in a row; the PRBS locks within the first frame |
| End of transmission | only while locked; two words in a row |

A stream LICH word corrected in two bits or fewer is at least six bits from every other codeword (the extended
Golay code's distance is 8), so the decode needs no second check against a runner-up.

The 24-symbol BERT word is two symbols from an LSF preamble: a hard slice can take one for the other. The level
fit rejects that hit, and a frame is BERT only when its payload is the PRBS9 sequence.

A mode that receives only after these checks lost no frame and accepted no false one in two hours of noise in an
earlier prototype (one false frame every 150 s without them; measured on a host model).

### 5.3 The soft modem with short syncs (`core/air`)

The soft modem fits its patterns only where its gate lets them through (air-interface.md 6). The gate wants all of a
pattern's large steps but one among its last 17 symbols. M17's 8-symbol words have three large steps each, and two
of them are exact negations of the other two (stream = -LSF, BERT = -packet). Any sample that fails one pattern's
gate passes its negation's, so with M17's patterns the gate lets **every** sample of noise through (host model:
6 % of noise samples for P25's sync, 50 % for one M17 word, 100 % for a negated pair). Three changes in the shared
soft modem, for every mode:

| Change | What | Effect |
|---|---|---|
| Negated pairs | At open, the modem finds pattern pairs of one length whose symbols are negations; it computes the shared sums once, and a negative slope of one is the other's positive one | the fit's work for M17 about halves |
| The lock window (`sync_period_syms`) | While locked on a profile whose syncs come at a fixed period, the fit runs only within two symbols of where the next one is due; out of lock it runs everywhere | the load with a signal falls to the window (about 2 % of samples) |
| Outer gate (if measured to need it) | For patterns of outer symbols only: a second bit per symbol, set when the sample's magnitude is above the inner level; fitted only where all but one are set | in noise, a few percent of samples; decided on the host model and the bench (11) |

Without a signal the receiver searches everywhere, so the cost in noise is the first number to measure on each radio
(`air.rx_work_us` / `air.rx_span_us`, the debug link's air section).

### 5.4 The receive copy

| Item | Measured on one radio with an HR_C7000, digital audio set-up | Use |
|---|---|---|
| Scale | 5.7-6.0 counts per Hz of deviation | the tap's `counts_per_khz` |
| Low end | +0.8 dB at 10 Hz, +0.6 dB at 50-100 Hz; no high-pass down to about 6 Hz | M17's long runs of one symbol survive |
| High end, dB re 1 kHz | 2 kHz -0.1, 2.5 kHz -1.4, 3 kHz -4.1, 3.3 kHz -12.4, 3.6 kHz -32.8 | about 1 dB of receive penalty against a full band (simulation) |
| Drift against an SDR | under 1 ppm | |

A receive path with a 300 Hz high-pass (an FM audio set-up) can't receive M17: the soft modem's DC tracker can't
undo it, and the fit refuses a tap whose low edge is above 48 Hz. The provider keeps the RF chip in its digital audio
set-up during a session. On an HR_C6000 board the copy's low end in that set-up has not been measured directly; an
NXDN 9600 receive through it decoded every frame, which needs the same response.

### 5.5 Late entry and the call

| Event | Receiver |
|---|---|
| LSF | the call's DST, SRC, TYPE and META at once |
| Stream frame, no LSF yet | LICH chunks are kept by counter. The TYPE (chunk 2: LSF bytes 10-14) gives the CAN and the data type before the rest: voice may play from then, once the CAN passes (8.3). After all six chunks the CRC of the rebuilt LSF must be 0; until then the caller is shown as not known |
| LICH counter | taken from each frame; never computed from the frame number (the 15-bit number wraps after 21.8 minutes and the two drift apart) |
| META changes | taken at superframe boundaries (counter 0) only |
| Last frame | frame number bit 15, or an end-of-transmission word, or the signal lost: the call ends |
| A gap | frames placed by counting while the framer coasts; a lost frame goes to the voice path as bad (9.2) |

## 6. Transmit

### 6.1 Which transmitter

A modem chip's physical layer mode sends whatever dibits the core writes, with its own pulse and two-point,
DC-coupled modulation ([modem-hrc6000.md](modem-hrc6000.md) 10.3, [modem-hrc7000.md](modem-hrc7000.md) 10.2). The core
sends everything as symbols: preamble, LSF, frames, end marker. No soft modem transmit half is needed.

The chips' pulse is DMR's: root raised cosine with roll-off 0.2, not 0.5. The provider answers
`AIR_FIT_SHAPE_APPROX`. Simulation puts the mismatch at +0.6 dB at 10 % frame errors and +1.2 dB at 1 %; timing
error costs far more than the pulse. An M17 receiver's level estimate takes its gain from the sync, so no transmit
level scale is applied unless a bench measurement shows one helps (as P25's `C4FM_SCALE` does).

### 6.2 Key-up and end

| Item | Rule |
|---|---|
| Lead-in | The provider's set-up time (tens of ms) goes out as idle symbols, `0x77`: more preamble. The engine still sends a whole 192-symbol preamble of its own |
| Underrun in a stream | The engine never lets the provider run dry inside a stream: with no codec frame ready it sends a stream frame of encoded silence (9.3). The provider's idle symbols are for its own underruns only, which break the frame |
| End | The last stream frame has frame number bit 15 set; the end marker follows; the provider holds the carrier until its queue is empty and one idle chunk has gone ([modem-hrc7000.md](modem-hrc7000.md) 10.2 step 4), so the end marker's tail is not cut at key-down |
| CSMA | Packets wait for a clear channel (no lock and no signal for one frame), then send with probability 1/4 in each 40 ms slot (M17 1.4.6). Voice is sent on PTT, as on FM |

### 6.3 Measured, one radio with an HR_C7000 (an earlier prototype, the chip's physical layer mode)

| Item | Measured |
|---|---|
| Decoded by | an SDR decoder, an MMDVM hotspot (bit error rate 0.8-1.3 % at -72 dBm), the M17 network and a phone client; a 78-frame voice clip arrived byte for byte |
| Symbol rate | 4800.00 symbols/s, 0 to -3 ppm |
| Deviation | 27.0 Hz per modulation step at 434 MHz (outer/inner 2.99, linear); RadioFoundry's scale assumes about 25 Hz from another unit, so about 8 % high there (receivers take their level from the sync) |
| Low end | a constant outer level droops under 0.2 % in 300 ms |
| High end | a ±3 alternation (2.4 kHz) reads 7.7 % below the steady level |
| Residual | after a run of -3 symbols a single +3 can be read as +1: about 1 symbol in 1,000, the same in every run (deterministic intersymbol interference) |
| Slot timing | the last byte of each 30 ms slot went out in the next slot unless written one slot late; that set-up ran continuous mode with both TX RAM halves written after the FM path had keyed the transmitter. RadioFoundry's provider stays on its own measured timeslot recipe ([modem-hrc7000.md](modem-hrc7000.md) 10.2); M17 needs nothing else from the chip |
| Spectrum | 99 % occupied bandwidth 9.6-10.5 kHz, adjacent channel power -28 to -34 dBc at ±12.5 kHz |

Not measured: the weak-signal cost of the chip's pulse against an MMDVM receiver; the HR_C6000's pulse against any
M17 receiver; VHF deviation (the modulation byte may clamp).

## 7. Addresses (callsigns)

Six bytes, big endian: a base-40 number (M17 app. A).

| Character | Value |
|---|---|
| space (padding) | 0 |
| `A`-`Z` | 1-26 |
| `0`-`9` | 27-36 |
| `-`, `/`, `.` | 37, 38, 39 |

| Rule | |
|---|---|
| Encoding | the first character is the least significant digit; at most 9 characters; trailing spaces don't count |
| Lower case | taken as upper case when typed; any other character refuses the text |
| 0 | reserved: never sent; a DST of 0 received is shown as not known |
| `0xFFFFFFFFFFFF` | broadcast, destination only. Shown and typed as `ALL` (and `@ALL`); a blank destination is broadcast |
| `0xEE6B28000000` and above | reserved for applications: shown as hex |
| Example | `AB1CD` encodes as `0x0000009FDD51` |

Gateways may rewrite a broadcast DST as the text `ALL` (base 40, not broadcast): the receiver treats both as a call to
all (13).

## 8. Data modes

### 8.1 BERT

| Side | Behavior |
|---|---|
| Transmit | preamble (-3 first), BERT frames of the running PRBS9 sequence until stopped, end marker |
| Receive | the PRBS locks from the first frame's decoded bits; then bits compared, counted per frame: bits, errors, frames, frames lost (placed by counting), relocks |
| Where | the debug link (`m17 bert`), the view keys `m17.bert.*`, and the HIL tests (11). No screen at first |

The counters measure the whole receive chain (tap, soft modem, framer, Viterbi) against a bench transmitter, so BERT
is the yardstick for every receive change.

### 8.2 Text messages

| Side | Behavior |
|---|---|
| Send | an LSF (SRC ours, DST the addressee or broadcast, packet TYPE, the channel's CAN), the packet's frames, end marker. CSMA as 6.2. Up to 821 bytes of text |
| Receive | frames gathered by number; the CRC checked over the whole packet; a type 0x05 text to us or to broadcast goes to the inbox with the sender's callsign. Others are counted and dropped |
| No acknowledgement | M17 Part I defines none: "sent" means it went on air |

### 8.3 Channel access number (CAN)

Four bits in every LSF. A channel has a CAN (0-15) it sends. On receive it plays calls with its CAN, or every call
when the channel says so (the CAN squelch off); a call with another CAN is shown and not played.

## 9. Voice

### 9.1 The codec

A stream frame of data type voice carries 128 bits: two Codec 2 3200 frames of 64 bits, the first 20 ms first
(M17 2.8.1). One codec frame is one 20 ms, 160-sample audio block at 8 kHz (`hal/hal_audio.h`). The codec is
`c2fx`, a fixed-point MIT library outside this tree (`third_party/c2fx`), built with `CONFIG_M17_VOICE`.

### 9.2 Receive

The engine queues each stream frame's two codec frames; the audio block callback takes one per block and decodes it
(`core/m17/m17Voice.c`, after `core/p25/p25Voice.c`). Playback starts once two stream frames are queued (80 ms) and
one more block has passed. A frame whose Viterbi decode corrected more bits than a limit, a frame placed by counting
(no sync), and a block with nothing queued during a call go to the decoder as lost: it repeats the last frame with
falling level, then mutes.

### 9.3 Transmit

While a transmission is on, the audio block callback encodes each microphone block; the engine takes two encoded
frames per stream frame. With none ready it sends the silence frame: the encoder's output for a block of zeros, made
once when the session opens. The speaker is silent meanwhile.

### 9.4 Not played

Encrypted streams, voice + data streams (Codec 2 1600), data-only streams, and the authentication and signature
frames of a signed stream (frame numbers 0x7FFB-0x7FFF and 0xFFFF; M17 3.2.4) are not decoded. The first three are
shown as such.

## 10. The radio core, codeplug, UI

M17 is a channel mode (`RADIO_MODE_M17`): the radio core runs it with the board in its digital mode, as P25 and NXDN
(`core/radio/radio_m17.c`, `radio_air_ops_t`). It is offered where the board's provider gives the profile receive or
transmit (`radio_m17_fits`): no capability flag, no `board_t` field. Its memory is lent by idle parts (P25's engine,
the DMR vocoder's working memory) while it runs. It needs no stock codec in flash. The stored channel is kind 6
([m17-codeplug.md](m17-codeplug.md)).

| Item | Where |
|---|---|
| Own callsign | the kind's radio-wide record; blank = the radio name's first word, as [m17-codeplug.md](m17-codeplug.md) 1.2 gives it. PTT is refused without a valid one |
| Channel: CAN, CAN squelch, destination | the tag's parameter block |
| Receive screen | caller (or the extended callsign's originator), destination, CAN, voice / data / encrypted, META text |
| Talk to | the channel's destination; `ALL`, `ECHO`, `INFO`, `UNLINK` from a short list on the radio |

## 13. Gotchas (candidates for gotchas.md, an M17 section)

| # | Lesson |
|---|---|
| 1 | Negated sync pairs defeat the soft modem's gate: every noise sample is fitted (5.3) |
| 2 | A 300 Hz high-pass in the receive path is fatal to an 8 kHz 4FSK soft receiver: keep the RF chip in its digital audio set-up |
| 3 | Late entry is required, not optional: hotspot traffic often loses its first frames and the LSF |
| 4 | Count the LICH per frame, not as the frame number modulo 6 |
