# M17

M17 conventional operation on the air interface ([air-interface.md](air-interface.md)): stream mode (voice), packet
mode (text messages) and BERT mode (bit error rate test). Source: *M17 Protocol Specification, Part I: Air
Interface*, version 2.1.1 (19 November 2026), cited below as "M17" with its section numbers. Switch: `CONFIG_M17`,
with `CONFIG_M17_PACKET` and `CONFIG_M17_VOICE` ([build-config.md](../build-config.md)). Which radios could carry it:
[feature-matrix.md](../feature-matrix.md).

**Licence of the source.** The M17 document is GFDL-1.3-or-later; its code samples (appendix listings) are
GPL-2.0-or-later. This page is written in our own words from the document's prose, tables and formulas. Numeric
protocol constants (sync words, polynomials, puncture patterns, the randomizer sequence, the interleaver formula, the
address alphabet) are interoperability facts and are used as such. Never copy the document's text or code, and never
open another M17 implementation's source ([CLEANROOM.md](../CLEANROOM.md)).

## 2. Frame fields and FEC

All payload coding reuses `core/fec` ([air-interface.md](air-interface.md) 1). Only the CRC, the puncture patterns,
the interleaver and the randomizer are new, in `core/m17/m17_frame.c`.

| Step | What | Where |
|---|---|---|
| CRC | 16 bit, polynomial `0x5935`, initial `0xFFFF`, not reflected, no final XOR. Check values: empty input `0xFFFF`, `A` `0x206E`, `123456789` `0x772B`, the bytes 0 to 255 `0x1C31`. A whole valid LSF (CRC included) gives 0 | M17 2.6 |
| Convolutional code | rate 1/2, constraint length 5, G1 = 1 + D³ + D⁴, G2 = 1 + D + D² + D⁴, output G1 then G2, four zero tail bits. This is `fec_conv` with masks `{ 0x19, 0x17 }`, the code NXDN uses ([nxdn.md](nxdn.md) 2) | M17 app. C |
| Golay | extended Golay(24,12): data bits 23-12, check bits 11-1, parity bit 0. Bit for bit `fec_golay24_encode` / `fec_golay24_decode` (each of the 12 generator rows checked) | M17 app. D |
| Puncturing | P1 (LSF): 61 entries, 46 kept: a 1, then fifteen times `1 0 1 1`; applied over the 488 coded bits. P2 (stream, BERT): 12 entries, 11 kept (every twelfth bit dropped). P3 (packet): 8 entries, 7 kept (every eighth dropped). The decoder gives a dropped bit the soft value 0 | M17 app. E |
| Interleaver | quadratic permutation of the 368 payload bits: bit x goes to (45x + 92x²) mod 368 | M17 app. F |
| Randomizer | the 368 payload bits XOR a fixed 46-byte sequence, most significant bit first, the same for every frame (a table of 46 bytes) | M17 1.4.4, app. B |

Bit types: type 1 is the content, type 2 after the convolutional code, type 3 after puncturing, type 4 after
interleaving; randomizing comes last before the sync is added (M17 2.2).

## 3. Frames

### 3.1 Link setup frame (LSF)

| Bytes | Field | Notes |
|---|---|---|
| 0-5 | DST | destination address (7) |
| 6-11 | SRC | source address (7) |
| 12-13 | TYPE | 3.5 |
| 14-27 | META | 112 bits; its kind is TYPE's (3.5) |
| 28-29 | CRC | over bytes 0-27 |

Coding: 240 bits + 4 tail bits → convolutional code (488) → P1 (368) → interleave → randomize, behind the LSF sync.
One LSF per transmission, straight after the preamble (M17 2.5, 2.7).

### 3.2 Stream frame

| Part | Bits | Coding |
|---|---|---|
| LICH: 40 bits of the LSF (one sixth), LICH counter (3 bits, 0-5), 5 reserved bits (0) | 48 | four Golay(24,12) words: 96 |
| Frame number (16 bits: bit 15 set on the last frame, bits 14-0 count from 0 and wrap after 0x7FFF) + payload (128 bits) | 144 | + 4 tail bits, convolutional code (296), P2 (272) |

LICH 96 + payload 272 = 368 bits, interleaved and randomized together (M17 2.8.1). LICH counter n carries LSF bytes
5n to 5n + 4.

**Superframe.** Six stream frames carry one whole LSF, so a receiver that missed the LSF has it after at most
240 ms (M17 2.8.2). Only META may change during a stream, and only at a superframe boundary.

### 3.3 Packet frame

25 data bytes and a 6-bit field: on all but the last frame, bit 5 clear and bits 4-0 the frame number; on the last,
bit 5 set and bits 4-0 the number of valid bytes in it. 206 bits + 4 tail → 420 → P3 (368) → interleave → randomize.
A packet is 1 to 33 frames after its LSF: at most 823 bytes of data plus its CRC (3.4) (M17 2.9).

### 3.4 Packet contents

A data type (1 to 4 bytes, the UTF-8 length encoding; 0-127 in one byte), the data, then the CRC (2) over both
(M17 3.3.2). Data types used here:

| Type | Content | Here |
|---|---|---|
| 0x05 | Text message: UTF-8, ending with a NUL | sent and received (8.2) |
| others (RAW, AX.25, APRS, 6LoWPAN, IPv4, Winlink) | | received and dropped, counted |

### 3.5 TYPE

TYPE is a big-endian 16-bit value at LSF bytes 12–13. Bit 0 is the least significant bit.
The field constants are in `core/m17/m17.h`. See M17 3.1.2, tables 3.2–3.8.

| Bits | Field | Values |
|---|---|---|
| 0 | Mode | 0 packet, 1 stream |
| 1–2 | Stream data type | 00 reserved, 01 data, 10 voice (Codec 2 3200), 11 voice + data (Codec 2 1600 plus 64 data bits). Packet mode sends 00. |
| 3–4 | Encryption | 00 none, 01 scrambler, 10 AES, 11 reserved for other use. Packet mode sends 00. |
| 5–6 | Encryption subtype | Key length for scrambler or AES. With no encryption, selects META: 00 text, 01 GNSS, 10 extended callsign, 11 reserved. |
| 7–10 | CAN | 0–15 (8.3) |
| 11 | Stream signature flag | 0 unsigned, 1 signed. RadioFoundry sends 0 in both modes. |
| 12–15 | Reserved | Sent as 0 |

### 3.6 META

| Kind | Here |
|---|---|
| Text | Home shows the blocks available so far, in order. The control byte's high nibble is the declared mask (1, 3, 7 or 15). Its low nibble must select exactly one block in that mask. A zero control byte clears the text. A packet accepts only 0x11 or zero. |
| Extended callsign | The first six bytes give the originator. Home shows that callsign and the LSF source on a separate **via** line. An absent or invalid originator leaves the LSF source as the caller. |
| Position | not read |
| None, nonce (encrypted) | |

Text has up to four 13-byte UTF-8 blocks. The receiver accepts them in any order and replaces a block when it repeats.
Contiguous blocks can share a UTF-8 glyph. Unavailable blocks separate runs. Home trims trailing padding, substitutes
unsupported or malformed glyphs, and shortens the bottom line if needed. Neither text nor extended callsign is
interpreted when TYPE indicates encryption. See M17 3.1.3.

### 3.7 BERT frame

197 bits of the PRBS9 sequence (x⁹ + x⁵ + 1) per frame, coded as a stream payload is: + 4 tail bits, convolutional
code (402), P2 (369), the last bit dropped (368), interleave, randomize. No LSF (M17 2.10, app. G).

| Part | Symbols | Content |
|---|---|---|
| Preamble | 192 (40 ms) | +3 and -3 alternating. +3 first before an LSF, -3 first before BERT, so its last symbol is opposite the sync's first (M17 1.4, 2.4) |

| Frames | 192 each | stream, packet or BERT frames |
| End of transmission | 192 | the word `555D` repeated (M17 1.4.5) |

## 5. Receive

### 5.1 Which receiver

A modem chip's own correlator takes only 24-symbol patterns of outer symbols that recur through a transmission
([air-interface.md](air-interface.md) 4, [modem-hrc6000.md](modem-hrc6000.md) 10.1). M17's recurring syncs are 8
symbols; the only 24-symbol run is a preamble's tail plus the LSF word, once per transmission. So M17 is received
through a board's discriminator tap and the soft modem (`AIR_FIT_RX | AIR_FIT_SOFT`). A board without a tap can
transmit M17 and not receive it.

The soft modem's fit (`air_softmodem_rx_fit`) needs the tap's band to reach 2640 Hz (0.55 × 4800) and, for four
levels, down to 48 Hz. The pulse's spectrum reaches 3600 Hz ((1 + 0.5) × 2400); a copy specified to 3000 or 3400 Hz
trims its tail (5.4).

### 5.2 Sync confirmation (the head hook)

An 8-symbol pattern with one error allowed turns up by chance in random data and noise several times a second. The
framer cuts a frame at every candidate, and the mode's head hook (`air_mode_t.head`) accepts it only on proof:

| Pattern | Confirmed by |
|---|---|
| LSF | the whole frame: the CRC over the decoded LSF is 0 |
| Stream | the LICH: all four Golay words decode, at most 2 bits corrected each (`fec_golay24_decode` returns 0-3, or -1; 3 and -1 are rejected); counter 0-5; reserved bits 0 |
| Packet | a fresh CRC-valid packet LSF, syncs in consecutive frame slots, at most 20 hard-bit disagreements per frame, and the whole-packet CRC. For one frame, two EOT words in the slot after the packet frame confirm it |
| BERT | after a preamble only (the 24-symbol pattern), or two BERT frames in a row; the PRBS locks within the first frame |
| End of transmission | only while locked; two words in a row |

A stream LICH word corrected in two bits or fewer is at least six bits from every other codeword (the extended
Golay code's distance is 8), so the decode needs no second check against a runner-up.

The 24-symbol BERT word is two symbols from an LSF preamble: a hard slice can take one for the other. The level
fit rejects that hit, and a frame is BERT only when its payload is the PRBS9 sequence.

Packet reception starts with an explicit LSF whose CRC passes and whose TYPE selects packet mode. Each next sync
must start 37 to 43 ms after the previous frame's start (40 ms ± 3 ms, the widest copy-clock accuracy a provider
publishes), beginning at the LSF. Nonfinal frames are numbered from zero. A new LSF, a confirmed stream or BERT
takeover, a squelched chunk, or an RX reset clears the previous candidate. One missing copy half does not, while
the next frame can still land in that window; a gap of a whole frame does. The framer may search between
provisional frames. The expected slot and the same LSF still govern the next frame. A frame past the window, a
decode failure, or a broken frame number consumes the LSF, so a later frame needs a fresh LSF. A sync earlier
than the window is ignored.

The decoder counts received hard bits that disagree with the decoded Viterbi path. The count covers the 368
transmitted bits and excludes punctures. The provisional limit is inclusive at 20 per frame. The receiver records
the sample count and peak of these measurements, including above-limit frames. A negative decoder result or a
count over 20 increments the FEC reject counter. The receiver counts a final CRC failure once confirmation
reaches the CRC check. A valid CRC increments the CRC pass counter, including when CAN squelch then rejects the
packet and increments its own counter.
These counters and the peak are cleared by an M17 RX reset or a new session.

A mode that receives only after these checks lost no frame and accepted no false one in two hours of noise in an
earlier prototype (one false frame every 150 s without them; measured on a host model).

### 5.3 The soft modem with short syncs (`core/air`)

Each sync has its own acquisition gate. Long words use a step check and an error bound. Short words use an
exact sign check. The modem evaluates the samples around an acquired candidate at full resolution
([air-interface.md](air-interface.md#6-sample-taps-and-the-soft-modem)). While the modem has timing lock, the
fit runs from two symbols before the next expected sync until it finds one. If the tap's magnitude steps by
half or double, the modem drops its timing lock and opens the search. This lets the link-setup word be fitted
at the new carrier's level even after a noise lock.

The framer indexes the signs of the newest eight symbols into a flash table of possible syncs. A pattern
excluded by the table has already exceeded its error allowance in those eight signs. The framer still checks
the full pattern and levels for each candidate. Once a sync is found for the unit, the framer can skip the
checks for that unit's remaining symbols.

At 72 MHz, a 256-sample half from an 8 kHz tap represents 32 ms or 2,304,000 cycles. The receive budget is
30% for the busiest half (691,200 cycles) and 15% on average in noise (345,600 cycles). The host regression
(`airRxWorkTest`) covers seeded noise and clean text at 2,190 Hz and 2,540 Hz outer deviation and limits the
work counts per half. Timing estimates and target measurements are described in
[gotchas.md](gotchas.md#18-air-interface).

### 5.4 The receive copy

| Item | Measured on one radio with an HR_C7000, digital audio set-up | Use |
|---|---|---|
| Scale | 5.7-6.0 counts per Hz of deviation | the tap's `counts_per_khz` |
| Low end | +0.8 dB at 10 Hz, +0.6 dB at 50-100 Hz; no high-pass down to about 6 Hz | M17's long runs of one symbol survive |
| High end, dB re 1 kHz | 2 kHz -0.1, 2.5 kHz -1.4, 3 kHz -4.1, 3.3 kHz -12.4, 3.6 kHz -32.8 | about 1 dB of receive penalty against a full band (simulation) |
| Drift against an SDR | under 1 ppm | |

A receive path with a 300 Hz high-pass (an FM audio set-up) can't receive M17: the soft modem's DC tracker can't
undo it, and the fit refuses a tap whose low edge is above 48 Hz. The provider keeps the RF chip in its digital audio
set-up during a session. On an HR_C6000 board the copy's low end in that set-up has not been measured directly; an
NXDN 9600 receive through it decoded every frame, which needs the same response.

### 5.5 Late entry and the call

| Event | Receiver |
|---|---|
| LSF | the call's DST, SRC, TYPE and META at once |
| Stream frame, no LSF yet | The TYPE in chunk 2 gives the CAN and the data type early. The CAN gate can pass frames from then (8.3). Until a full LSF passes its CRC check, Home shows an ellipsis for the caller. |
| LICH counter | taken from each frame; never computed from the frame number (the 15-bit number wraps after 21.8 minutes and the two drift apart) |
| META changes | Chunk 0 starts a new candidate. A gap or a missing chunk invalidates the assembly. Only a consecutive 0–5 candidate with a valid CRC replaces the last valid snapshot. Every valid snapshot can update META. Call end, a new call and retuning clear the accumulated text. |
| Last frame | frame number bit 15, or an end-of-transmission word, or the signal lost: the call ends |
| A gap | frames placed by counting while the framer coasts; a lost frame goes to the voice path as bad (9.2) |

## 6. Transmit

### 6.1 Which transmitter

A modem chip's physical layer mode sends whatever dibits the core writes, with its own pulse and two-point,
DC-coupled modulation ([modem-hrc6000.md](modem-hrc6000.md) 10.3, [modem-hrc7000.md](modem-hrc7000.md) 10.2). The core
sends everything as symbols: preamble, LSF, frames, end marker. No soft modem transmit half is needed.

The chips' pulse is DMR's: root raised cosine with roll-off 0.2, not 0.5. The provider answers
`AIR_FIT_SHAPE_APPROX`. Simulation puts the mismatch at +0.6 dB at 10 % frame errors and +1.2 dB at 1 %; timing
error costs far more than the pulse. An M17 receiver's level estimate takes its gain from the sync, so no transmit
level scale is applied unless a bench measurement shows one helps (as P25's `C4FM_SCALE` does).

### 6.2 Key-up and end

| Item | Rule |
|---|---|
| Lead-in | The provider's set-up time (tens of ms) goes out as idle symbols, `0x77`: more preamble. The engine still sends a whole 192-symbol preamble of its own |
| Underrun in a stream | The engine never lets the provider run dry inside a stream: with no codec frame ready it sends a stream frame of encoded silence (9.3). The provider's idle symbols are for its own underruns only, which break the frame |
| End | The last stream frame has frame number bit 15 set; the end marker follows; the provider holds the carrier until its queue is empty and one idle chunk has gone ([modem-hrc7000.md](modem-hrc7000.md) 10.2 step 4), so the end marker's tail is not cut at key-down |
| CSMA | Packets wait for a clear channel (no lock and no signal for one frame), then send with probability 1/4 in each 40 ms slot (M17 1.4.6). Voice is sent on PTT, as on FM |

Packet carrier sense uses the raw status poll on the selected, tuned M17 receiver after a 50 ms settle.
A sample is clear when the M17 framer has no lock, the chip reports no carrier, raw noise is at least 52,
and raw RSSI is at or below −100 dBm. The fixed thresholds are the default squelch thresholds for noise
and digital signal strength. Missing readings or an unavailable receive path count as busy. The 25 ms
polls must span at least one 40 ms frame without a busy sample or a gap greater than 25 ms. This sampled
policy can miss a short carrier between readings. Each eligible 40 ms slot has a 1-in-4 chance of sending,
and a grant expires by the next status poll. Five seconds from admission ends the wait as busy.

## 7. Addresses (callsigns)

Six bytes, big endian: a base-40 number (M17 app. A).

| Character | Value |
|---|---|
| space (padding) | 0 |
| `A`-`Z` | 1-26 |
| `0`-`9` | 27-36 |
| `-`, `/`, `.` | 37, 38, 39 |

| Rule | |
|---|---|
| Encoding | the first character is the least significant digit; at most 9 characters; trailing spaces don't count |
| Lower case | taken as upper case when typed; any other character refuses the text |
| 0 | reserved: never sent; a DST of 0 received is shown as not known |
| `0xFFFFFFFFFFFF` | broadcast, destination only. Shown and typed as `ALL` (and `@ALL`); a blank destination is broadcast |
| `0xEE6B28000000` and above | reserved for applications: shown as hex |
| Example | `AB1CD` encodes as `0x0000009FDD51` |

Gateways may rewrite a broadcast DST as the text `ALL` (base 40, not broadcast): the receiver treats both as a call to
all (13).

## 8. Data modes

### 8.1 BERT

| Side | Behavior |
|---|---|
| Transmit | preamble (-3 first), BERT frames of the running PRBS9 sequence until stopped, end marker |
| Receive | the PRBS locks from the first frame's decoded bits; then bits compared, counted per frame: bits, errors, frames, frames lost (placed by counting), relocks |
| Where | the debug link (`m17 bert`), the view keys `m17.bert.*`, and the HIL tests (11). No screen at first |

The counters measure the whole receive chain (tap, soft modem, framer, Viterbi) against a bench transmitter, so BERT
is the yardstick for every receive change.

### 8.2 Text messages

| Side | Behavior |
|---|---|
| Send | an LSF (SRC ours, DST the addressee or broadcast, packet TYPE, the channel's CAN), the packet's frames, end marker. CSMA as 6.2. Up to 821 bytes of text |
| Receive | after LSF integrity, CAN and packet CRC checks, clear type 0x05 text addressed to the applied callsign, binary broadcast, or base-40 `ALL` enters the inbox |
| No acknowledgement | M17 Part I defines none. "Sent" means the provider confirmed drain without an underrun and the radio dropped carrier |

The radio task owns one queued send and checks the selected channel, actual frequencies, applied callsign
and CAN before keying through the ordinary air transmit path. An explicit message destination works
independently of the temporary voice destination. PTT or BERT can cancel the wait. PTT held through
an on-air packet can start voice after the radio unkeys. Each admitted request ends with one result,
including channel busy, a changed route, a transmit guard, no usable address or fit, a transmit
refusal, a failed or unconfirmed drain, or a transmit time-out.

A message has valid UTF-8 followed by one final NUL. The receiver validates up to 821 text bytes and keeps up to
143 display bytes plus NUL, ending at a whole glyph. It records the original text byte count and whether display
capacity cut the text. Unsupported glyphs and control characters map to safe display characters. The LSF must
carry a usable source address. The inbox keeps the verified raw LSF source as the sender and reply target,
including for broadcasts. META is call display metadata.

The handset accepts up to 143 display characters (ASCII and ISO-8859-1). The message service converts those
bytes to valid UTF-8 and the radio checks the wire length separately, still at most 821 text bytes. A blank body
is not sent. The handset's "Sent" is the on-air result above, not a delivery receipt.

The RX hook normally runs on the provider's deferred task and can also run synchronously during open.
It validates and converts using scratch in the active session's lend block. The radio task layer supplies
scheduler-held copies for publication and observers. Packets and decode scratch stay in the session.
An in-place receiver restart pauses inbox admission until the receiver and framer discard old packet state.

The four-entry RAM inbox keeps the newest entries first and evicts the oldest when full. Each entry has a
milliseconds-since-boot timestamp, an unread flag and a nonzero ID. Readers can copy an entry by index or ID
and mark it read or delete it by ID. The receive sequence and last received ID record arrivals across polling
intervals and survive entry deletion. Inbox entries survive retunes and air session close. Radio core
initialization empties the inbox and resets its receive sequence and IDs.

Unsupported type, invalid address and malformed text have separate counters. The radio task folds the
receiver's protocol counters and FEC peak into the radio totals at each poll, before an RX reset, and when a
session closes. The totals survive retunes and mode changes. Radio core initialization and the M17 stats reset clear the
packet totals. The stats reset also clears the live protocol counters and preserves the inbox and receive sequence.

### 8.3 Channel access number (CAN)

Every stream or packet LSF carries the channel's CAN (0–15). Stream mode repeats those LSF bytes in LICH chunk 2.
BERT sends its preamble, PRBS9 test frames, and an end marker. These frames carry no CAN.

With CAN squelch on, the receiver releases voice frames and packets only after it knows that the incoming CAN
matches the configured receive CAN. It reads the CAN from the LSF or from LICH chunk 2 on late entry. Caller
reporting continues for every CAN, with the callsign available after the LSF passes its CRC check. With squelch off,
receive delivery ignores the CAN. The VFO defaults to squelch off.

## 9. Voice

### 9.1 The codec

A stream frame of data type voice carries 128 bits: two Codec 2 3200 frames of 64 bits, the first 20 ms first
(M17 2.8.1). One codec frame is one 20 ms, 160-sample audio block at 8 kHz (`hal/hal_audio.h`). The codec is
`c2fx`, a fixed-point MIT library outside this tree (`third_party/c2fx`), built with `CONFIG_M17_VOICE`.

### 9.2 Receive

The engine queues each stream frame's two codec frames; the audio block callback takes one per block and decodes it
(`core/m17/m17Voice.c`, after `core/p25/p25Voice.c`). Playback starts once two stream frames are queued (80 ms) and
one more block has passed. A frame whose Viterbi decode corrected more bits than a limit, a frame placed by counting
(no sync), and a block with nothing queued during a call go to the decoder as lost: it repeats the last frame with
falling level, then mutes.

### 9.3 Transmit

While a transmission is on, the audio block callback encodes each microphone block; the engine takes two encoded
frames per stream frame. With none ready it sends the silence frame: the encoder's output for a block of zeros, made
once when the session opens. The speaker is silent meanwhile.

### 9.4 Not played

Encrypted streams, voice + data streams (Codec 2 1600), data-only streams, and the authentication and signature
frames of a signed stream (frame numbers 0x7FFB-0x7FFF and 0xFFFF; M17 3.2.4) are not decoded. The first three are
shown as such.

## 10. The radio core, codeplug, UI

M17 is a channel mode (`RADIO_MODE_M17`): the radio core runs it with the board in its digital mode, as P25 and NXDN
(`core/radio/radio_m17.c`, `radio_air_ops_t`). It is offered where the board's provider gives the profile receive or
transmit (`radio_m17_fits`): no capability flag, no `board_t` field. It borrows the DMR vocoder's working memory
and the engine blocks P25 and NXDN own while those parts are idle. It needs no stock codec in flash. The stored channel is kind 6
([m17-codeplug.md](m17-codeplug.md)).

The lend pool offers 8-byte-aligned blocks, largest first. The M17 engine needs one contiguous region. A
`CONFIG_M17_VOICE` build places codec scratch first, then the engine, then codec state with space for the voice
queues. If the complete placement fails, it tries the engine alone in the original pool. The debug link reports
`m17.voice_mem` for the active session and `m17.engine_bytes` for the engine size in voice builds.

| Item | Where |
|---|---|
| Own callsign | the kind's radio-wide record; blank = the radio name's first word, as [m17-codeplug.md](m17-codeplug.md) 1.2 gives it. A voice or packet PTT without a valid one is refused as "M17: set your callsign". BERT is exempt |
| Home | mode M17, a talk line `CAN n` then the destination (broadcast is "All"), and `CAN n` on the power line. The destination is the one PTT calls, not an address heard |
| Receive only | a provider that cannot transmit M17 refuses PTT as "M17: receive only". A channel marked receive-only stays the shared "This channel is RX only" |
| Channel: CAN, CAN squelch, destination | the tag's parameter block |
| Home during receive | caller, destination, received CAN, status, and any META text or **via** callsign. **All** covers both the broadcast encoding and the gateway spelling `ALL`. BERT and carrier activity use the ordinary receive presentation. |
| Quick 2: CAN | the M17 VFO's transmit CAN, 0–15 |
| Quick 3: CAN squelch | on accepts only the M17 VFO's CAN. Off accepts all CANs |
| Quick 8: Talk to | a temporary destination for the selected M17 channel or VFO |

Received M17 text appears in the shared Messages inbox, merged by age with DMR and APRS. The banner, list and
message show the LSF source callsign. Opening marks a message read. A stored text cut is marked separately from
the screen's shortened preview. Message frames retain the stable M17 ID: if the entry is evicted, the view
reports it deleted and cannot act on another entry. When the selected M17 channel or VFO can transmit packets
and is not receive-only, Messages offers **New M17 message** and an open message offers Reply "OK", Reply
"On my way", **Write...** and Delete, plus Full message when the text is long or was cut. Otherwise the open
message offers Full message and Delete. Call and sender PTT are not available. The inbox is volatile.

**New M17 message** opens `m17-message-to`. The field starts as the channel or VFO's programmed destination;
the temporary Talk to choice is left alone. Blank or ALL is broadcast, shown as **All**. An invalid address
shows **Not an M17 address** and stays in the editor. OK opens the shared composer (`compose`, then
`message-text` for **Write...**). **#** on an M17 list row, and the reply rows on the open message, address the
verified source as a private destination, including when the original message was a broadcast. The radio
rechecks the selected generation when the message is submitted. A busy transmitter stays on the composer so
the send can be tried again. Success is "Sent to ...". A failure names the reason and the destination.
"Delivered" remains the DMR confirmation only. A missing callsign, a receive-only channel or radio, or no
selected M17 channel explains why the send did not start and does not fall through to DMR or APRS.

In the callsign and destination editors, a rejected first press shows the character warning and leaves the text
as entered. Pressing that key again starts a fresh entry. Once a key inserts a character, a rejected step in its
multi-tap cycle leaves that character in place.

**CAN** and **CAN squelch** open `m17-can` and `m17-can-squelch` on the M17 VFO. Each picker focuses the
current value. OK queues the value for the selected generation and returns to Quick. Back cancels. The radio
task updates the session's M17 VFO settings without clearing a temporary destination. The CAN and filter
survive a retune. Restart restores CAN 0 and CAN squelch Off. A transmission already in progress keeps its CAN
until it ends. Stored M17 channels use their programmed CAN and squelch.

Quick shows the effective transmit destination, with broadcast shown as **All**. Select **Talk to** to open
`m17-talk-to`. Its rows are **Default**, `ALL`, `ECHO`, `INFO`, `UNLINK` and **Other…**, in that order.
**Default** shows the base destination for the channel or VFO and clears the temporary choice. OK queues a choice
and returns to Quick. Back leaves the picker for Quick, and Back from Quick reaches Home.

**Other…** opens `m17-talk-to-other` with the shared **Talk to** prompt and the effective destination as its
initial text, blank for broadcast. The shared nine-character destination editor folds lowercase and accepts
spaces inside the address. OK uses the same parser as the stored channel editor. Blank or `ALL` selects broadcast.
An invalid address shows **Not an M17 address** and leaves the editor open. Back deletes and leaves once the field
is empty. Hold Back goes Home where supported. Leaving without OK discards the text. The channel editor loads
and saves the programmed destination as part of the channel record. Quick choices apply only to the current selection.

The picker captures the base and generation at entry, and **Other…** retains that generation until submission.
If the selected generation has changed or the UI cannot queue the request, the picker shows a message.

The radio task owns one temporary destination in RAM. A stored selection is identified by its zone, position and
resolved channel number. A VFO selection uses its index and RX and TX frequencies. Changing that identity,
switching out of M17, choosing a different dual-watch pane or restarting clears the choice. A retune on the
same context and starting or stopping dual watch on that selection preserve it. Zone and VFO scans and the
debug-only dual scan follow the tuned channel.

`radio_req_m17_talk_to(generation, dst)` queues the selected view's generation and a packed 48-bit destination.
Zero clears the choice and all ones selects broadcast. The selected view reports the base and effective destinations
and the selected CAN and CAN squelch, with generation zero when no M17 selection is available. A change to the base destination invalidates any
older generation for that selection and preserves its temporary choice. During a full dual watch, the selected view
follows the selected pane while the running view and debug-link fields follow the engine on the tuned channel.

The engine uses the choice only when tuned to the matching selection. An idle engine applies it immediately.
A transmission keeps its current destination through the end marker. The radio applies a pending change before
rekeying. If the receiver is on the other watch pane, the choice takes effect when the selected pane is tuned,
including the tune for PTT. Talk to keeps the callsign, CAN, CAN squelch, BERT selection and stored settings.

The receive snapshot carries its own CAN and destinations. When TYPE is unknown, Home shows an ellipsis in place
of the CAN and status. Once TYPE is available, status is evaluated in order: **Other CAN** when the configured
filter rejects the incoming CAN, **Encrypted**, **Voice + data**, **Data**, then **Voice**. **Voice** describes the
received stream type. The active radio receiver has no playback hook. When space is tight, Home gives the
receive lines priority over the normal channel and transmit fields. The Dual watch presentation identifies the tuned
receive pane above the same call details.

## 13. Gotchas (candidates for gotchas.md, an M17 section)

| # | Lesson |
|---|---|
| 1 | Negated sync pairs defeat the soft modem's gate: every noise sample is fitted (5.3) |
| 2 | A 300 Hz high-pass in the receive path is fatal to an 8 kHz 4FSK soft receiver: keep the RF chip in its digital audio set-up |
| 3 | Late entry is required, not optional: hotspot traffic often loses its first frames and the LSF |
| 4 | Count the LICH per frame, not as the frame number modulo 6 |
| 5 | A blank or `ALL` destination is broadcast `0xFFFFFFFFFFFF`; 0 is reserved |
| 6 | Hotspots seen on air: about 18 % low deviation (outer ±1965 Hz), DST rewritten to the text `ALL`, the last stream frame without its end bit before the end marker, the first one or two frames lost |
| 7 | An EVM figure from an analyzer with a roll-off 0.5 filter is meaningless on a 0.2 transmitter: judge by symbol errors against a known vector |
| 8 | A receive capture for calibration must start before key-up, or the preamble and LSF are never seen |
